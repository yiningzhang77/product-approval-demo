# 商家商品申请审批模块-可维护性增强需求梳理

## 一、文档目的

本文用于整理当前项目后续增强需求，先作为讨论稿，不直接进入实现。

本轮增强目标不是引入复杂权限系统，而是在现有“商家商品申请审批模块”基础上，让页面结构、查询筛选、数据导出和基础资料维护更接近真实后台系统，同时保持 Java 初学者能够理解和讲清楚。

## 二、当前项目现状

当前已实现的基础功能：

- 商家提交商品申请页面：`/apply`
- 管理端审批列表页面：`/admin/applications`
- 管理端 CSV 导出接口：`/admin/applications/export`
- 商品申请表：`product_apply`
- 商品图片上传到本地 `uploads` 目录
- 商品价格大于 1000 元时自动标记价格告警
- 管理端可以审批通过或驳回

当前不足：

- 商家端和管理端页面边界还不清晰。
- 商家端没有“我的申请”页面，也没有只查看当前商家的限制。
- 商品分类仍然是手动输入，没有独立的分类基础资料表。
- CSV 导出目前偏全量导出，后续应改为导出当前筛选结果。
- 管理端筛选能力不足，不能按商家、分类、状态、告警、时间范围组合查询。
- 没有侧边栏和工作台页面，系统结构感不够强。

## 三、系统角色

### 1. 商家端

商家端关注的问题：

- 我提交了哪些商品？
- 我的申请现在是什么状态？
- 有没有被驳回？
- 为什么被驳回？
- 有没有价格告警？
- 能不能导出我当前筛选出来的申请？

核心规则：

- 商家端只能看到当前商家的数据。
- 商家端的所有查询条件里，必须始终带上当前商家限制。
- 本项目暂时不做真实登录，通过 URL 参数模拟当前商家，例如 `/merchant/dashboard?merchantId=1`。

### 2. 管理端

管理端关注的问题：

- 查看所有商家的商品申请。
- 查看哪些申请待审批。
- 查看哪些申请存在高价告警。
- 查看某个商家的申请情况。
- 查看某个分类下的申请情况。
- 按商品名称搜索。
- 审批通过或驳回。
- 导出当前筛选结果。
- 维护商品分类。

核心规则：

- 管理端可以看到全部商家的申请数据。
- 管理端的筛选维度比商家端更多，尤其需要支持按商家筛选。

## 四、侧边栏规划

### 1. 商家端侧边栏

```text
商家端
├─ 商家工作台
├─ 提交商品申请
└─ 我的申请
```

### 2. 管理端侧边栏

```text
管理端
├─ 审批工作台
├─ 商品申请管理
│  ├─ 全部申请
│  ├─ 待审批
│  ├─ 已通过
│  └─ 已驳回
├─ 价格告警
└─ 基础资料
   └─ 商品分类
```

说明：

- 左侧菜单可以增强项目的真实感。
- 菜单项不一定都对应独立页面或独立查询逻辑。
- “全部申请 / 待审批 / 已通过 / 已驳回”必须复用同一个管理端申请列表页面，只是默认筛选参数不同。
- “商家端-我的申请”也是一个列表页面，不因为不同状态拆成多套页面。
- 页面整体风格参考常见后台系统：左侧侧边栏、顶部标题或面包屑、右侧主体内容区。
- 列表页主体参考“商品列表”类后台页面：上方集中放筛选条件，中间放状态入口和列表，下方放导出按钮。
- 工作台页面参考“概况”类数据面板：上方统计卡片，中间待办事项，下方可以预留图表或最近数据列表。

## 五、商家端功能需求

### 1. 商家工作台

展示当前商家的统计数据，页面形态参考后台“概况”数据面板。

统计项：

| 统计项 | 说明 |
| --- | --- |
| 总申请数量 | 当前商家的全部申请数量 |
| 待审批数量 | 当前商家状态为 `PENDING` 的申请数量 |
| 已通过数量 | 当前商家状态为 `APPROVED` 的申请数量 |
| 已驳回数量 | 当前商家状态为 `REJECTED` 的申请数量 |
| 价格告警数量 | 当前商家 `isWarning = true` 的申请数量 |

关键规则：

- 所有统计都必须只统计当前商家。

页面结构建议：

```text
顶部：
商家端 / 商家工作台

数据卡片区：
总申请数量 | 待审批数量 | 已通过数量 | 已驳回数量 | 价格告警数量

待办提醒区：
待审批申请数量
被驳回申请数量
价格告警申请数量

最近申请区：
最近提交的商品申请列表，展示少量记录即可
```

实现说明：

- 第一版可以先做统计卡片和最近申请列表。
- 图表不是必须，避免一开始引入复杂前端库。
- 所有统计和最近申请都必须带当前商家限制。

待讨论点：

- 后续是否需要在页面顶部显示当前商家名称。
- 当 URL 中没有 `merchantId` 或 `merchantId` 不存在时，页面应该提示错误还是默认使用第一个商家。

### 2. 提交商品申请

商家提交商品申请，提交后：

- 状态为 `PENDING`。
- 系统自动判断是否价格告警。
- 商品分类不能手填，必须从 `product_category` 表中选择。

提交字段建议：

| 字段 | 说明 |
| --- | --- |
| 商家 | 当前商家，不建议由用户随意填写 |
| 商品分类 | 从启用的商品分类中下拉选择 |
| 商品名称 | 必填 |
| 商品价格 | 必填，BigDecimal |
| 商品图片 | 支持 jpg / jpeg / png |
| 商品简介 | 可选 |
| 备注 | 可选 |

### 3. 我的申请

商家端“我的申请”页面只展示当前商家的申请数据。

页面定位：

- “我的申请”是一个单独页面。
- 页面内集中放多个筛选条件，类似后台商品列表页的筛选区。
- 不要为“待审批 / 已通过 / 已驳回 / 价格告警”分别写多套页面。
- 状态 Tab 或侧边栏状态入口，本质上都是给同一个列表页面传入不同查询参数。

建议筛选项：

| 筛选项 | 是否必要 | 说明 |
| --- | --- | --- |
| 商品名称关键词 | 必要 | 按商品名模糊搜索 |
| 商品分类 | 必要 | 从分类表下拉选择 |
| 审批状态 | 必要 | 全部 / 待审批 / 已通过 / 已驳回 |
| 是否价格告警 | 建议 | 全部 / 是 / 否 |
| 申请时间范围 | 可选 | 后续有时间再做 |
| 价格范围 | 可选 | 当前版本不是必须 |

页面结构建议：

```text
左侧：
商家端侧边栏

顶部：
商家端 / 我的申请

筛选区：
商品名称：[________]
商品分类：[全部分类 ▼]
审批状态：[全部状态 ▼]
是否告警：[全部 ▼]
[搜索] [重置]

状态入口：
全部 | 待审批 | 已通过 | 已驳回 | 价格告警

列表区：
申请ID | 商品分类 | 商品名称 | 价格 | 状态 | 是否告警 | 告警原因 | 申请时间 | 审批时间 | 审批备注

底部：
[导出当前筛选结果 CSV]
```

状态筛选可以做成 Tab：

```text
全部
待审批
已通过
已驳回
价格告警
```

推荐路径设计：

```text
/merchant/applications
/merchant/applications?status=PENDING
/merchant/applications?status=APPROVED
/merchant/applications?status=REJECTED
/merchant/applications?isWarning=true
/merchant/applications?status=PENDING&categoryId=1&keyword=水杯
```

关键规则：

- 商家端查询必须始终限制为当前商家。
- 商家端不支持手动筛选其他商家。
- 商家端状态 Tab 只是快捷筛选，不是新页面。
- 商家端导出按钮必须保留当前筛选条件。
- 商家端列表默认按申请时间倒序排列，最新申请显示在最上面。

## 八、CSV 导出规则

CSV 导出不应该是固定全量导出，而应该导出当前页面筛选结果。

### 1. 通用规则

- 所有 CSV 导出必须跟随当前页面筛选条件。
- 列表查询和 CSV 导出尽量共用同一个查询方法，避免两套逻辑不一致。
- 页面上的导出链接需要保留当前筛选参数。
- CSV 需要加 UTF-8 BOM，保证 Excel 打开中文不乱码。

### 2. 商家端导出

按钮文案：

```text
导出当前筛选结果 CSV
```

导出范围：

- 当前商家。
- 当前筛选条件下的申请记录。

示例：

如果商家筛选了：

```text
分类 = 食品饮料
状态 = 已驳回
关键词 = 牛奶
```

那么导出时只导出当前商家中符合这些条件的申请记录。

### 3. 管理端商品申请管理导出

按钮文案：

```text
导出当前筛选结果 CSV
```

导出接口要接收和列表查询相同的筛选参数：

- `merchantId`
- `categoryId`
- `keyword`
- `status`
- `isWarning`
- `startDate`，暂不实现，后续增强
- `endDate`，暂不实现，后续增强

规则：

- 如果没有筛选条件，则导出全部申请。
- 如果有筛选条件，则只导出当前筛选结果。

### 4. 管理端价格告警导出

默认筛选：

```text
isWarning = true
```

规则：

- 页面底部导出时，只导出当前价格告警筛选结果。
- 如果用户继续筛选商家、分类、状态、商品名称，导出结果也要同步这些筛选条件。

### 2. 商品分类表 product_category

### 3. 商家表 merchant

已确认新增简单 `merchant` 表，不做登录、不做账号密码。

用途：

- 用 `merchant_id` 明确限制商家端数据范围。
- 管理端可以按商家下拉筛选。
- 商家端通过 URL 参数模拟当前商家，例如 `merchantId=1`。
- 不引入 Spring Security、JWT、权限系统。

建议字段：

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| name | 商家名称 |
| enabled | 是否启用 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

初始数据建议：

- 百姓超市
- 万隆商城
- 测试商家

## 十三、阶段性小结

本轮需求增强后的系统可以概括为：

```text
商家端
├─ 商家工作台
│  └─ 当前商家的统计数据
├─ 提交商品申请
│  └─ 商品分类从 product_category 表下拉选择
└─ 我的申请
   ├─ 按商品名称搜索
   ├─ 按商品分类筛选
   ├─ 按审批状态筛选
   ├─ 按是否告警筛选
   └─ 导出当前商家的筛选结果

管理端
├─ 审批工作台
│  └─ 全局统计数据，具体呈现方式待讨论
├─ 商品申请管理
│  ├─ 全部申请
│  ├─ 待审批
│  ├─ 已通过
│  └─ 已驳回
│
│  支持筛选：
│  ├─ 商家
│  ├─ 商品分类
│  ├─ 商品名称
│  ├─ 审批状态
│  ├─ 是否告警
│  └─ 申请时间倒序排列
│
├─ 价格告警
│  └─ 默认筛选 isWarning = true
├─ 基础资料
│  └─ 商品分类
│     ├─ 分类名称搜索
│     ├─ 启用状态筛选
│     ├─ 新增分类
│     ├─ 修改分类
│     └─ 启用 / 停用
└─ 数据导出
   └─ 导出当前筛选结果或全部申请
```

最重要的实现原则：

- 商家端和管理端共用申请数据，但数据范围不同。
- 商家端永远只能看当前商家的申请。
- 管理端可以看全部申请。
- 商品分类从基础资料表中选择，不再手填。
- 当前商家通过 URL 参数 `merchantId` 模拟。
- 新增简单 `merchant` 表，但不做登录和账号密码。
- 申请列表和 CSV 导出必须共用同一套筛选逻辑。
- 列表默认按申请时间倒序排列，时间范围筛选后续增强。
- 驳回时必须填写原因，通过时可以为空并默认“审批通过”。
- 价格告警页复用申请列表，不单独写死一套页面。
- 不引入 Spring Security、JWT、Redis、微服务等复杂技术。
